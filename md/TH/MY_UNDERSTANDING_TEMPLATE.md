## Backend

**1. HTTP method แต่ละตัวในแอปของคุณหมายถึงอะไร — GET, POST, PUT or PATCH, และ DELETE? ทำไมเราถึงใช้ method ต่างกัน แทนที่จะใช้ POST สำหรับทุกอย่าง?**

_คำตอบของคุณ:_

- GET: ใช้ดึงข้อมูลมาโชว์ เช่น ดึงรายการสินค้าใส่ตาราง
- POST: ใช้สร้างข้อมูลใหม่ เช่น กรอกฟอร์มแล้วกดเซฟเพิ่มสินค้า
- PUT / PATCH: ใช้แก้ข้อมูลเดิม
- DELETE : ใช้ลบข้อมูลออกจากระบบ
- ที่ใช้method ต่างกัน แทนที่จะใช้ POST สำหรับทุกอย่าง สาเหตุเพราะ
  - อ่านง่าย แค่มอง Method ก็รู้เลยว่าจะอ่าน สร้าง แก้ หรือลบ ไม่ต้องเสียเวลาเปิดดูโค้ดข้างใน ไม่งง
  - GET, PUT, DELETE ยิงซ้ำกี่รอบผลก็เหมือนเดิม แต่ POST ยิงซ้ำเมื่อไหร่ ข้อมูลซ้ำจะถูกสร้างเพิ่มทันที
  - ตั้งค่าความปลอดภัยได้ง่ายเช่น ให้ลูกค้าใช้ได้แค่ GET ส่วน Admin ถึงจะใช้ POST, PUT, DELETE ได้

**2. `express.json()` คืออะไร และจะเกิดอะไรขึ้นถ้าคุณไม่ใส่มัน?**

_คำตอบของคุณ:_

- express.json() เป็นเหมือนตัวแปลภาษาที่แปลงข้อมูล JSON ที่ส่งมาจากหน้าเว็บให้กลายเป็น Object ที่ Node.js ให้อ่านเข้าใจและเอาไปใช้งานต่อได้
- ถ้าไม่ใส่จะอ่านข้อมูลไม่ได้ เพราะไม่ได้แปลงภาษามา

**3. `req.body`, `req.params`, และ `req.query` ต่างกันอย่างไร? ยกตัวอย่างจริงจาก API ของคุณสำหรับแต่ละตัว**

_คำตอบของคุณ:_

- ทั้ง 3 ตัวคือ Object ที่ Express.js ใช้รับข้อมูลจาก Frontend แต่รับมาจากคนละตำแหน่งตามการใช้งาน
- req.params คือ ข้อมูลที่ฝังอยู่ในเส้นทาง URL ตรงๆ ใช้ระบุ ID เพื่อเจาะจงสินค้าชิ้นนั้นๆ
  - ตัวอย่าง: ยิงมาที่ /products/3 → ได้ req.params.id คือ "3" (สั่งลบหรือดูสินค้าชิ้นที่ 3)
  - // GET /products/:id หรือ DELETE /products/:id
    - const product = products.find((p) => p.id === req.params.id); (บรรทัดที่ 29 ไฟล์ products.js)

- req.body คือ ข้อมูลชุดใหญ่ที่ซ่อนมากับ Request เป็น JSON ใช้ส่งข้อมูลเพิ่มหรือแก้ไขสินค้า
  - ตัวอย่าง: ส่ง { "name": "Baby Wipes", "price": 199 } → ได้ req.body เป็น Object นำไปเซฟลง Database
  - // POST /products หรือ PUT /products/:id
    - const { name, price, quantity } = req.body; (บรรทัดที่ 44 ไฟล์ products.js)

- req.query คือ ข้อมูลเสริมต่อท้าย URL แบบ ?key=value ใช้กรอง ค้นหา เรียงลำดับ หรือแบ่งหน้า
  - ตัวอย่าง: ยิงมาที่ /products?search=baby → ได้ req.query.search คือ "baby" เอาไปเสิร์ชหาเฉพาะสินค้าเด็กที่มีคำว่า baby
  - // GET /products?search=baby
    - const { search } = req.query; (บรรทัดที่ 9 ไฟล์ products.js)

**4. HTTP status codes คืออะไร? ระบุรายการ status code ทุกตัวที่คุณใช้ใน API และอธิบายว่าทำไมถึงเลือกใช้ในแต่ละสถานการณ์**

_คำตอบของคุณ:_

- HTTP Status Codes คือ รหัสตอบกลับจาก Server ที่บอกให้ Frontend รู้ทันทีว่า Request ที่ยิงมานั้น สำเร็จหรือพังเพราะอะไร
- Status Code ที่ใช้ใน API มีตามนี้
  - 200 OK ใช้ตัวนี้เพราะ รหัสตัวนี้ใช้ตอบกลับเวลาดึงข้อมูลสำเร็จ (GET), อัปเดตข้อมูลเสร็จ (PUT), หรือลบข้อมูลเรียบร้อย (DELETE)
  - 201 Created ใช้ตัวนี้เพราะ รหัสตัวนี้ใช้ตอบกลับเวลาเพิ่มสินค้าชิ้นใหม่ลงระบบสำเร็จ (POST) เพื่อบอกชัดเจนว่าข้อมูลใหม่ถูกสร้างขึ้นแล้ว
  - 400 Bad Request ใช้ตัวนี้เพราะ รหัสตัวนี้ใช้ใช้แจ้งเตือนเวลา Frontend ส่งข้อมูลมาไม่ครบหรือไม่ตรงตามเงื่อนไข (เช่น ลืมใส่ชื่อสินค้าหรือราคา)
  - 404 Not Found ใช้ตัวนี้เพราะ รหัสตัวนี้ใช้บอกเวลา Frontend ส่ง id สินค้าที่ไม่มีอยู่ในระบบเข้ามา (เช่น พยายามจะลบหรือแก้ไขสินค้าที่ถูกลบไปแล้ว)
  - 500 Internal Server Error ใช้ตัวนี้เพราะ รหัสตัวนี้ใช้ดักจับใน Centralized Error Handling เวลาเกิด Bug หรือ Error ที่ไม่ได้คาดคิดขึ้นในฝั่ง Backend

**5. middleware คืออะไร? อธิบายด้วยคำพูดของคุณเองว่ามันทำอะไร พร้อมยกตัวอย่าง 1 อย่างจากโค้ดของคุณ**

_คำตอบของคุณ:_

- Middleware คือ ตัวกลางที่คอยดักจับ Request และ Response ระหว่าง Frontend กับ Controller
  โดย Middleware จะช่วยแปลงข้อมูลที่ส่งมาให้อยู่ในรูปที่พร้อมใช้งาน, ช่วยจดบันทึกประวัติการเรียกใช้งานระบบม, ช่วยดักจับ Error รวมไว้ที่จุดเดียว ก่อนส่งตอบกลับ frontend
- ตัวอย่างที่ทำ Custom Middleware: Request Logger (จากไฟล์ sever.js บรรทัดที่ 11-15)
  - app.use((req, res, next) => {
    console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
    next();
    });

**6. ทำไม order ของ middleware ใน Express ถึงสำคัญ? จะเกิดอะไรขึ้นถ้า order ผิด?**

_คำตอบของคุณ:_

- order ของ Middleware สำคัญเพราะ Express ทำงานแบบเรียงลำดับจากบนลงล่าง (Waterfall) Request จะวิ่งผ่านทีละด่านตามที่เราเขียนสั่งไว้
- ถ้า order ผิด จะเกิดขึ้นตามนี้
  - อ่านข้อมูลไม่ได้ (undefined) ถ้าเรียกใช้ req.body ก่อน ใส่ express.json() ข้อมูลส่งมาเท่าไรก็อ่านไม่ออก
  - Error Handler ไม่ทำงาน ถ้าเอาตัวจับ Error ไปไว้ ก่อน Route Handler เมื่อระบบเกิด Bug จะจับ Errorไม่ได้ ทำให้ Request ค้างหรือเซิร์ฟเวอร์ดับ

**7. อธิบายทีละขั้นตอนว่าเกิดอะไรขึ้นบน server เมื่อมี POST request ถูกส่งไปที่ `/products`**

_คำตอบของคุณ:_

ขั้นตอนการทำงานบน Server เมื่อมี POST Request ไปที่ /products

- รับ Request โดย Server ต้อนรับ Request เข้ามา และดูว่าเป็น POST ที่ไป /products
- แปลงข้อมูล (express.json) โดย แกะแกะกล่อง Body ที่ส่งมาแล้วแปลงเป็น JSON ใส่ไว้ใน req.body
- ตรวจสิทธิ์ เช็ค Token ว่าผู้ใช้ล็อกอินหรือยัง (ถ้าไม่มี โดนไล่ออกทันที 401)
- ตรวจข้อมูล และ บันทึก โดยตรวจว่าส่งชื่อสินค้า และ ราคาสินค้ามาครบไหม (ถ้าไม่ครบ ส่ง 400), บันทึกสินค้าใหม่ลงใน Database
- ตอบกลับ (Response) โดยส่งรหัส 201 Created พร้อมข้อมูลสินค้าใหม่กลับไปให้ ลูกค้า
- ถ้า Database ล่มหรือระบบมี Bug จะส่งรหัส 500 Error กลับไปแทน เพื่อไม่ให้ Server พัง

**8. CRUD คืออะไร? จับคู่แต่ละ operation กับ HTTP method และ route ที่คุณใช้ใน API**

_คำตอบของคุณ:_

CRUD คือ คำสั่งพื้นฐานในการจัดการข้อมูล 4 อย่าง มีตามนี้ Create, Read, Update, และ Delete

- การจับคู่กับ HTTP Method และ Route ใน API
  - Create (สร้าง): ใช้ POST บน Route /api/v1/products ทำหน้าที่รับข้อมูลจากฟอร์ม แล้วสร้างสินค้าชิ้นใหม่เพิ่มลงในระบบ (products.push)
  - Read (ดึง/อ่านข้อมูล): ใช้ GET บน Route
    - /api/v1/products : สำหรับดึงรายการสินค้าทั้งหมด หรือกรองตามคำค้นหา ?search=
    - /api/v1/products/:id : สำหรับดึงข้อมูลสินค้าเฉพาะชิ้นตาม ID
  - Update (แก้ไข): ใช้ PUT บน Route /api/v1/products/:id ทำหน้าที่ค้นหาสินค้าตาม ID แล้วนำข้อมูลใหม่ไปอัปเดตแทนที่ข้อมูลเดิม
  - Delete (ลบ): ใช้ DELETE บน Route /api/v1/products/:id ทำหน้าที่ค้นหาสินค้าตาม ID แล้วลบสินค้านั้นออกจากระบบ (products.splice)

**9. API ของคุณตอบสนองอย่างไรเมื่อมีอะไรผิดพลาด — เช่น เมื่อ product ตาม ID ที่ระบุไม่มีอยู่จริง?**

_คำตอบของคุณ:_

- ถ้า ID ไม่มีอยู่จริง (GET /:id, PUT /:id, DELETE /:id) หรือกรอกข้อมูลไม่ครบ
  ระบบจะตัดการทำงานและส่ง HTTP Status Code (เช่น 404 Not Found หรือ 400 Bad Request) พร้อมส่งข้อความ JSON สั้นๆ ชัดเจนกลับไป ให้ Frontend

## Frontend & Integration

**10. CORS คืออะไร และแก้ปัญหาอะไร? ถ้าไม่ได้ config ไว้บน server ของคุณ คุณจะเห็นอะไรใน browser?**

_คำตอบของคุณ:_

CORS คือ ระบบความปลอดภัยของเบราว์เซอร์ ที่คอยควบคุมไม่ให้เว็บจากโดเมนหนึ่ง แอบยิง Request ไปดึงข้อมูลจาก API ของอีกโดเมนหนึ่ง โดยไม่ได้รับอนุญาต
โดย CORS จะช่วยป้องกันเว็บไซต์แปลกๆมาแอบใช้องค์ประกอบในเบราว์เซอร์ของผู้ใช้ยิง API ไปขโมยข้อมูลในเซิร์ฟเวอร์อื่น

ถ้าไม่ตั้งค่าบน Server เบราว์เซอร์จะ บล็อก Response ทำให้ Frontend อ่านข้อมูลไม่ได้ อาจจะมีข้อความขึ้นมาบอกว่ามีข้อความเตือนว่าโดนบล็อกด้วย

**11. แอป React ของคุณ fetch ข้อมูลจาก API ที่ไหน? อธิบายว่า `useEffect` ในโค้ดนั้นทำอะไร และทำไมถึงเรียก fetch ตรง ๆ ใน component body ไม่ได้**

_คำตอบของคุณ:_

- แอป React ดึงข้อมูลมาจาก Backend API ที่ Endpoint http://localhost:3001/api/v1/products
- useEffect ทำหน้าที่ ทำหน้าที่สั่งให้โค้ดดึงข้อมูลFetch API ทำงานเพียงครั้งเดียวตอนที่ Component ถูก Render ขึ้นหน้าจอครั้งแรก และควบคุมไม่ให้มีการดึงข้อมูลเรันซ้ำแบบไม่รู้จบ ด้วยการใส่Array ว่างเปล่า [] ไว้ท้าย useEffect
- ที่เรียก fetch ตรง ๆ ใน Component Body ไม่ได้ เพราะ จะทำให้เกิด Loop ไม่สิ้นสุด เพราะโค้ดจะทำให้ react ทำการ re-render ไปเรื่อยๆ และอาจทำให้เซิฟเวอร์ล่ม

**12. API base URL ของคุณถูกกำหนดไว้ที่ไหน และทำไมถึงเลือกเก็บไว้ตรงนั้น แทนที่จะ hardcode ไว้ในทุก fetch call?**

_คำตอบของคุณ:_

เก็บไว้ใน .env เพื่อง่ายต่อการเขียนโค้ดและแก้โค้ด รวมไปถึงเพื่อป้องกันความปลอดภัย ช่วยป้องกันไม่ให้ URL หรือ Key ที่เป็นความลับหลุดเข้าไปใน GitHub ที่ทุกคนมาดูได้

**13. เลือก action หนึ่งในแอปของคุณ — เช่น การลบ product อธิบายการเดินทางแบบครบวงจร (full round trip): เกิดอะไรขึ้นตั้งแต่ผู้ใช้คลิกปุ่ม ไปจนถึง request ไปถึง server จนถึงหน้าจออัปเดตด้วย list ใหม่**

_คำตอบของคุณ:_

- เมื่อผู้ใช้กดปุ่ม Delete เบราว์เซอร์จะรัน handleDeleteProduct(id) และเด้งกล่องยืนยัน หากกด OK จะเริ่มทำงาน
- จากนั้น Frontend จะยิง Request สั่ง fetch ด้วย DELETE Method ไปยัง Backend เช่น DELETE /api/v1/products/3 (ถ้าจะลบชิ้นที่มีไอดี 3)
- Backend ทำการลบข้อมูล โดย Express อ่าน req.params.id ค้นหาและลบสินค้านั้นออกจาก Array แล้วส่ง Response กลับมาด้วย 200 OK
- Frontend ทำการอัปเดตหน้าจอ โดย React เช็กว่าลบสำเร็จ จึงกรองสินค้านั้นออกจาก State ส่งผลให้หน้าจออัปเดตตารางใหม่ทันทีโดยไม่ต้องโหลดหน้าเว็บใหม่

**14. แอปของคุณแสดงอะไรให้ผู้ใช้เห็นระหว่างที่ข้อมูลกำลังโหลด และแสดงอะไรถ้า fetch ล้มเหลว (เช่น server ไม่ได้รันอยู่)? ทำไมเรื่องนี้ถึงสำคัญ?**

_คำตอบของคุณ:_

- ล้มแล้ว แสดง Error: Failed to fetch

**15. หลังจากที่คุณ add, edit, หรือ delete product แล้ว list บนหน้าจอของคุณอัปเดตโดยไม่ต้อง refresh หน้าเว็บ อธิบายว่าทำไมถึงเป็นแบบนั้น — อะไรที่ทำให้ React re-render ด้วยข้อมูลใหม่?**

_คำตอบของคุณ:_

- สาเหตุที่อัปเดตโดยไม่ต้อง Refresh เกิดจากระบบ State Management ของ React เมื่อมีการเปลี่ยนข้อมูล State React จะทำการRe-render ให้ทันทีแบบ Asynchronous
- สิ่งที่ทำให้เกิด React Re-render คือการเรียกใช้ฟังก์ชัน setProducts() หลังจัดการข้อมูลเสร็จ โดย Add จะนำสินค้าใหม่ไปต่อท้าย State เดิม, Edit จะนำข้อมูลใหม่ไปแทนที่ตัวเดิมใน State, Delete จะกรองเอาสินค้านั้นออกจาก State และเมื่อข้อมูล State เปลี่ยนแล้ว React จะทำการ Re-render หน้าจอใหม่ให้

**20. เลือก route (backend) หรือ component (frontend) 1 อันที่ AI ช่วยสร้าง โดยไม่ย้อนกลับไปดู AI chat history อธิบายว่ามันทำอะไรและทำไมถึงทำงาน ด้วยคำพูดของคุณเอง**

_คำตอบของคุณ:_
อยู่ในส่วนของ update เหมือนกัน ตอนแรกลองเขียนแบบที่คุณนิติสอนมาแล้วมันแสดงผลแปลกๆเป็น error เมื่อไม่ใส่จำนวนสินค้า

ตอนแรกเขียนแบบนี้
// ในกรณีใส่ข้อมูลไม่ครบตอนอัปเดต
if (!name || !price) {
return res.status(400).json({ error: "Name and price are required" });
}

ถามเอไอในส่วนนี้แก้เป็นแบบนี้
// ในกรณีใส่ข้อมูลไม่ครบตอนอัปเดต
if (!name || price == null) {
return res.status(400).json({ error: "Name and price are required" });
}

จากที่เข้าใจคือ ที่ต้องเปลี่ยนวิธีการเขียนเพราะการใช้เงื่อนไข !price จะมองว่าค่า 0 เป็น Falsy ทำให้เมื่อตั้งราคาสินค้าเป็น 0 บาท ระบบจะเข้าใจผิดว่าไม่ได้ระบุราคามาแล้วตีกลับเป็น Error แต่ถ้าเราใช้ price == null ซึ่งเป็นการตรวจสอบเฉพาะค่า null หรือ undefined ช่วยให้ระบบเช็กได้ถูกต้องว่ามีการส่งค่าราคามาหรือไม่ และให้บันทึกสินค้าที่มีราคาเป็น 0 บาทได้
